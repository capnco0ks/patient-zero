# Patient Zero — подготовка к защите

## От файлов до результата

Из папки проекта выполни:

```sh
javac -encoding UTF-8 -d out src/*.java
java -cp out Main
java tools/Check.java
java -cp out Bench
```

`tools/MakeVariant.java` уже создал четыре входных файла по ID 253109. ID влияет только на данные. Алгоритмы работают так же для любого другого варианта. `Input` читает строки A и B, геном, маркер и список рёбер с ценами тестов. Соседи хранятся в обе стороны, поскольку направление заражения не задано. `Main` вызывает три класса с алгоритмами, печатает девять чисел и передаёт их в `Render`. Тот вставляет входные данные, позиции маркера и выбранных людей в HTML-шаблон. Открой `output/outbreak.html`: сама страница отдельно пересчитывает ответы и рисует анимации.

## 1. Mutations — 102

В `Strains.editDistance` ячейка `d[i][j]` — сколько операций нужно, чтобы первые i букв A превратить в первые j букв B. Первая колонка равна i (всё удалить), первая строка равна j (всё вставить). Удаление стоит `d[i-1][j]+1`, вставка — `d[i][j-1]+1`, переход по диагонали — `d[i-1][j-1]` плюс 0 за совпадение или 1 за замену. Берём минимум, потому что эти варианты покрывают все способы обработать последние буквы. Соседние ячейки к этому моменту уже заполнены. Ответ лежит в правом нижнем углу.

Пример `AC → AGC`:

| A ↓ / B → | пусто | A | AG | AGC |
|---|---:|---:|---:|---:|
| пусто | 0 | 1 | 2 | 3 |
| A | 1 | 0 | 1 | 2 |
| AC | 2 | 1 | 1 | 1 |

Вставляем G. Индекс последней буквы префикса длины i равен i−1. Для строк длины a и b время и память O(ab).

## 2. Shared core — 1103

В `Strains.lcsLength` та же форма таблицы, но ячейка хранит длину общей подпоследовательности двух префиксов. Для пустого префикса длина 0. Совпали последние буквы — добавляем одну букву к диагонали. Различаются — их невозможно использовать как одну пару, поэтому берём лучший результат после пропуска последней буквы A или B.

У `ACGTT` и `AGTC` можно выбрать `AGT`: в первой строке пропускаем C, во второй не берём финальную C. Длина 3. Подстрока требовала бы идти подряд. После вставки одной буквы остальная строка может сдвинуться и всё равно войти в LCS. Время и память O(ab).

## 3. Marker hits — 7, First hit — 1628, Border length — 3

`Marker.prefixFunction` строит массив `pi`. В `pi[i]` лежит длина самого длинного собственного префикса отрезка `p[0..i]`, который также является его суффиксом. Собственный означает, что целый отрезок брать нельзя. Начинаем с `j = pi[i-1]` и пробуем продлить этот край на букву. Если не получилось, `pi[j-1]` даёт следующий допустимый край. Пример `ACGAC` → `[0,0,0,1,2]`. У твоего маркера `CCCTGCCC` общий край — `CCC`.

В `findAll` индекс i идёт вперёд по геному, j хранит число совпавших букв маркера. При несовпадении сокращаем j через pi и пробуем ту же букву генома ещё раз. Когда j дошло до длины маркера m, последнее совпадение стоит в i, а начало — `i-m+1`. После записи позиции сохраняем край через `pi[m-1]`. Поэтому для `AA` в `AAA` после совпадения на позиции 0 остаётся одна совпавшая A и находится позиция 1. Если совпадений нет, `Main` выводит −1 как первую позицию.

Почему линейно: каждый шаг по тексту увеличивает j максимум на единицу. Каждый откат уменьшает j, так что суммарное число откатов ограничено числом увеличений. Тот же аргумент работает для построения pi. Время O(n+m), память O(m+h), где h — число найденных позиций.

## 4. Shared words — 446

`Marker.sharedWords` сначала кладёт в HashMap хеш каждого окна B и список его стартовых позиций. Затем перебирает окна A. `firstHash` читает k букв как число по основанию 257 по модулю 1 000 000 007. `power` — вес первой буквы, то есть 257 в степени k−1 по тому же модулю. `slide` вычитает вес уходящей буквы, умножает остаток на 257 и добавляет новую букву. Прибавление MOD перед взятием остатка удерживает результат неотрицательным. Хеш сдвигается за O(1).

Равный хеш даёт кандидатов. После проверки букв `break` останавливает поиск для текущей позиции A. Даже если слово встречается в B много раз, одна позиция A даёт только единицу. Если то же слово появится в другой позиции A, её считаем отдельно. Например, при k=2 для `AAAA` и `AAA` ответ 3. В проекте k=12. Ожидаемое время при обычных операциях HashMap — O(a+b+kC), где C — число реально проверенных пар окон, память O(b). При множестве коллизий C может дойти до произведения чисел окон.

## 5. Tests needed — 28, Cheapest testing — 101, Longest chain — 20

`Outbreak.cheapestTests` укореняет дерево в 0. DFS передаёт родителя, чтобы обход не ушёл обратно по тому же ребру. `fillCosts` сначала считает состояния детей, потом узла. `take[v]` начинается с цены v. Когда v тестируется, ребро к каждому ребёнку уже покрыто, поэтому прибавляем минимум из состояний ребёнка. Когда v пропускается, каждый ребёнок обязан тестироваться, поэтому `skip[v]` складывает только их `take`. Для листа эти значения равны его цене и нулю.

В `choose` проходим от корня вниз. Если родитель пропущен, узел обязателен. Иначе выбираем меньшее состояние и при равенстве пропускаем узел. Так массив `tested` хранит сам набор людей. `Main` вызывает этот метод с единичными ценами для количества тестов и с реальными ценами для минимальной суммы.

Ручной пример из `tiny`: листья 3, 4, 5 дают пары (1,0), (5,0), (2,0). Узел 1 даёт (2,6), узел 2 — (4,2). Корень 0 даёт (7,6). Выбираем skip у корня, поэтому тестируем 1 и 2. Жадный выбор по числу рёбер ломается на звезде, где центр стоит 10, а три листа стоят по 1.

`longestChain` вызывает `height`. Для каждого ребёнка длина спуска через него равна 1 плюс его высота. Держим два самых длинных спуска через разных детей. Их сумма — самый длинный путь, высшая точка которого находится здесь. Наверх возвращаем только самый длинный спуск. Глобальный максимум обновляем в каждом узле, потому что путь может целиком лежать ниже корня. В `tiny` путь 3–1–0–2–5 имеет четыре ребра. Один узел даёт ноль рёбер. Оба алгоритма обходят дерево за O(v), память O(v) вместе со стеком рекурсии.
